[10] 4.1 字节定义详表
[11] 4.2 处理规则
[12] 4.2.1 取消标志语义 (byte 18-21)
[13] • 值 = 0→忽略对应的设定值, 保持原状态
[14] • 值 ≠ 0→按byte 0-7更新设定值 (需通过限值OOB检查)
[15] • 取消不影响其他字段正常更新 (与v1.0 “全封装失败”不同)
[16] 4.2.2 校准值应用 (byte 23-30)
[17] • 校准值 = 0 →不应用校准, 保持现有校准
[18] • 校准值 ≠ 0→写入Flash永久保存, 以后上报值 = 实测值 + 校准值
[19] • 范围超限→整包拒绝 (err=OOB)
[20] • 校准范围是相对的先加减值: 如标准温度25.0, temp_calibration=30→上报值=25.0+3.0=28.0℃
[21] 4.2.3 出厂限值 (byte 31-39)
[22] • 限值 = 0 →保持原有限值 (不更新)
[23] • 上限 < 下限→整包拒绝 (err=限值越界)
[24] • 限值超出表中有效范围→整包拒绝
[25] • 更新后限值作为target类参数的动态OOB校验基准
[26] • 保存到Flash持久化, 断电恢复
[27] 4.2.4 更新优先级
[28] 按顺序处理 (任何一步失败→整包拒绝):
[29] 1. 校验限值字段 (byte 31-39) 自身合法性
[30] 2. 校验校准值字段 (byte 23-30) 范围
[31] 3. 根据取消标志和限值, 校验设定值 (byte 0-17)
[32] 4. 全部检查通过→一次性应用所有更新
[33] 4.3 0x04 ACK响应 (2字节, 与v1.0一致)
[34] 五、请求示例 (完整字节交互)
[35] 5.1 示例1: 仅更新温度设定 25.0°C (其他均取消更新)
[36] 不设校准, 不改限值. 只改温度目标.
[37] AA 03 28 00FA 01F4 00D2 03E8 0000 0000 00 00 00 00 00 00 01 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 CS 55
[38] 关键字节解读:
[39] byte 0-1: 0x00FA = 250 = 25.0°C (新设定)
[40] byte 18 = 0x01 ≠ 0 → 应用温度
[41] byte 19 = 0x00 → 取消湿度更新 (保持现有湿度设定)
[42] byte 20 = 0x00 → 取消O2更新
[43] byte 21 = 0x00 → 取消CO2更新
[44] byte 23-30 = 全零 → 不应用校准
[45] byte 31-39 = 全零 → 不更新限值
[46] 5.2 示例2: 首次出厂设置
[47] 设定温度范围[20-40℃], 湿度[40-80%], O2[21-50%], UV最长30分钟, 雾化最长10分钟
[48] AA 03 28 ... 00 00 00 00 ... 28 14 50 28 32 15 1E 00 0A CS 55
[49] 关键字节:
[50] byte 31=0x28=40 (温度上限), byte 32=0x14=20 (温度下限)
[51] byte 33=0x50=80 (湿度上限), byte 34=0x28=40 (湿度下限)
[52] byte 35=0x32=50 (O2上限), byte 36=0x15=21 (O2下限)
[53] byte 37=0x1E=30 (UV上限分), byte 38=0x00=0 (UV下限=不限)
[54] byte 39=0x0A=10 (雾化上限分)
[55] 5.3 示例3: 校准温度+3.0℃, 湿度-1.5%
[56] byte 23-24 = 0x001E = +30 = +3.0℃ (×10格式)
[57] byte 25-26 = 0xFFF1 = -15 = -1.5% (补码)
[58] 模块上报值 = 实测值 + 3.0 (温度), -1.5 (湿度)
[59] 六、联调验收约定
[60] 6.1 双方必须同时确认的点
[61] 6.2 推荐联调步骤
[62] 1. 先联调v1.0 (但包扩展到40字节): 验证包解析正确
[63] 2. 联调取消标志: 部分字段更新成功
[64] 3. 联调校准: 验证值+上报值一致
[65] 4. 联调限值: 限值写入后, 用旧范围写参数发0x0A错误
[66] 5. 回测断电恢复: 校准和限值在重启后仍生效
[67] 七、签字确认
[68] 本协议一旦签字确认后冻结, 双方按此实现. 任何一方单方改动视为违约.
