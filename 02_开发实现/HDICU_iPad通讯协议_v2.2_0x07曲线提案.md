# HDICU-iPad 通讯协议 v2.2 — 0x07 曲线读取提案

**版本**: v2.2 草案 (rev 2, 含温度通道)
**日期**: 2026-04-28
**状态**: 待与 APP 端 (丁鹏) + 产品 确认后定稿
**变更**: 在 v2.1 基础上重新定义 `0x07/0x08` 为"读体征数值历史曲线"，支持 4 通道（心率 / 脉搏 / 血氧 / 体温）

---

## 一、背景

v1.0 ~ v2.1 协议把 `0x07` 命名为"读心电曲线"(ECG)，但当前硬件（JFC103 模块）**不支持 ECG 波形采集**，原 0x07 设计永远无法激活。

v2.2 把 `0x07/0x08` 重新定义为**"读体征数值历史曲线"**，对接 APP 端"最近 N 秒折线图"显示需求。

## 二、命令格式

### 2.1 请求 0x07 (1 字节)

```
AA 07 01 [CH] CS 55
```

| 字段 | 长度 | 说明 |
|------|------|------|
| CH (通道 ID) | 1 byte | 见 §3 通道定义 |

### 2.2 响应 0x08 (102 字节固定)

```
AA 08 66 [CH] [N] [DATA × 100B] CS 55
```
（LEN = 102 = 0x66）

| 字段 | 字节 | 说明 |
|------|------|------|
| CH (通道 ID) | 1 byte | 回显请求的通道 |
| N (有效采样点数) | 1 byte | 不同通道最大值不同, 详见 §3 |
| DATA | 100 byte | 采样数据载荷, 编码按通道而定 |

错误情况（未知通道）→ 主板返回 `AA FF 02 01 02 AE 55`（cmd unsupported）。

## 三、4 个通道定义

| CH | 通道 | 每点编码 | 每点字节 | 最大点数 | 窗口 | 范围 / 精度 |
|----|------|---------|---------|----------|------|-----------|
| **0x01** | **心率 HR** | uint8 | 1 B | **100** | **100 秒** | 0~250 bpm, 0=无效 |
| **0x02** | **脉搏 Pulse** | uint8 | 1 B | **100** | **100 秒** | 0~250 bpm, 0=无效 |
| **0x03** | **血氧 SpO2** | uint8 | 1 B | **100** | **100 秒** | 0~100 %, 0=无效 |
| **0x04** | **体温 Temp** | int16 BE ×10 | 2 B | **50** | **50 秒** | -100~+800 (-10.0~+80.0°C), -999=无效 |

**当前硬件特性**：
- HR 和 Pulse 都来自 JFC103 模块（数值相同，协议保留两通道是为未来双源扩展）
- SpO2 来自 JFC103
- Temp 来自 NTC（取 `temperature_avg` 平均值）
- 0x05~0xFF 未来扩展（湿度/O2/CO2 等），当前主板回 0xFF unsupported

**0x04 体温通道字节布局**（与其他通道差异化）：
```
byte 0:  CH = 0x04
byte 1:  N  (0~50)
byte 2..3: S0_high S0_low  (int16 BE, S0 = 最旧采样, ×10 单位)
byte 4..5: S1
...
byte 100..101: S49 (最新采样)
```

**0x01/0x02/0x03 字节布局**（HR/Pulse/SpO2 等 1 字节通道）：
```
byte 0:  CH
byte 1:  N  (0~100)
byte 2:  S0  (uint8, 最旧)
byte 3:  S1
...
byte 101: S99 (最新)
```

## 四、采样规则（主板侧实现）

1. **采样频率**: **1 Hz**（每秒 1 个点，所有通道同步）
2. **采样源**: 在 SystemTask 的 1Hz tick 中读取 `app_data.sensor` 的最新值
   - HR  → `sensor.heart_rate`（已含校准偏移）
   - Pulse → `sensor.heart_rate`（同 HR，JFC103 单源）
   - SpO2 → `sensor.spo2`
   - Temp → `sensor.temperature_avg`（已含校准）
3. **离线/无效处理**:
   - JFC103 离线 (`!jfc103_valid`): HR/Pulse/SpO2 写 0
   - NTC 无效: Temp 写 -999 (0xFC19)
4. **buffer 时序**:
   - S0 = 最旧的点（约 N×T 秒前，T=1s）
   - S_{N-1} = 最新的点（刚刚的 1Hz 采样）
   - APP 端从左到右画图（旧→新）即可
5. **开机后**: buffer 全填初始无效值。`N` 字段反映当前实际有效点数（< 最大值时）。第 N×T 秒后 N 达到上限并持续滚动

## 五、APP 端建议使用模式

### 进入"体征曲线"页面
```
APP → 0x07 CH=0x01     ← HR 曲线
APP ← 0x08 (102 byte)  ← 立即得到最近 100 秒 HR
APP → 0x07 CH=0x02     ← Pulse
APP ← 0x08
APP → 0x07 CH=0x03     ← SpO2
APP ← 0x08
APP → 0x07 CH=0x04     ← Temp
APP ← 0x08 (50 个 int16)
```
4 帧请求 + 4 帧响应 ≈ 4 × 107B = 428 byte，115200 波特率约 38ms 完成。**页面打开瞬间就有完整历史曲线**。

### 停留期间实时滚动
- **推荐**: 每秒 1 次 `0x05` 读体征 + `0x01` 读参数（取 temp_avg），APP 自己 append 最新点到本地 buffer 滚动
  - 流量小（25B/s + 50B/s ≈ 75B/s）
  - APP 自己维护展示 buffer
- **替代**: 每秒 4 次 `0x07` 重新拉全量（流量大但简单）
- **最佳**: 进页面 0x07 bootstrap, 停留期 0x05+0x01 polling, 切回页面 0x07 重新对齐

### 离开页面
停止 polling 即可。主板 4 个 buffer 一直在累，下次回来 0x07 拿到的就是最新。

## 六、协议优先级

按 v2.1 已有规则补充 0x08 响应（高→低）:

```
0x02 > 0x06 > 0x04 > 0x08 > 0xFF
```

## 七、CRC / 时序约束

- 与 v2.1 一致: CS = `(CMD + LEN + 所有 DATA byte) & 0xFF`
- iPad 请求间隔: 建议 1Hz 起步，最快 5Hz
- 主板响应: 100ms 内
- 主板 1Hz 采样精度: ±100ms

## 八、主板实现要点（参考，不影响协议）

```c
// 新增 App/data/curve_buffer.c/h
typedef struct {
    uint8_t  hr_buf[100];       // HR 1B/点 × 100
    uint8_t  pulse_buf[100];    // Pulse 1B/点 × 100
    uint8_t  spo2_buf[100];     // SpO2 1B/点 × 100
    int16_t  temp_buf[50];      // Temp 2B/点 × 50
    uint8_t  hr_n, pulse_n, spo2_n;   // 有效点数 (0~100)
    uint8_t  temp_n;                  // (0~50)
    uint8_t  hr_w, pulse_w, spo2_w;   // 写指针 (0~99)
    uint8_t  temp_w;                  // (0~49)
} CurveBuffer_t;

// SystemTask 1Hz tick:
curve_push_1hz(&app_data);
  // hr_buf[hr_w] = sensor.heart_rate; hr_w = (hr_w+1)%100; if hr_n<100 hr_n++;
  // ... 其他 3 通道类似, temp 通道用 50 容量

// ipad_protocol IPAD_CMD_READ_CURVE:
//   parse data[0] = CH
//   按 CH 分发到对应 buffer
//   按时间序输出 (oldest first):
//     起点 = (write_idx - n + cap) % cap   (cap = 100 或 50)
//     依次输出 n 个点 (剩余位填 0/0xFC19)
//   组帧 102B 发送
```

预估代码量 ~120 行（4 通道+边界处理），RAM 占用 ≈ 350 字节，主板编译大小增量 < 1.5KB。

## 九、协议向后兼容

- v2.1 客户端发 0x07 → v2.2 主板返回 102B 数据格式（CH + N + payload）
- v2.2 客户端 → v2.1 主板（未升级）：主板回 `AA FF 02 01 02 AE 55`，APP 应有 fallback（用 0x05+0x01 polling）
- 不影响其他命令（0x01/0x03/0x05/0x09/0x0A/0x0B 全部不变）
