# CN11 链路诊断包 — 给烧录人员

**目的**：验证屏幕板 → 主板的 CN11 串口链路是否正常工作（无需重新烧录固件）

**前提**：板子上已烧录 Stage 5 固件（含 CN11 双发改动）

---

## 操作步骤（3 分钟）

### 1. 接线

| 接 | 到 |
|----|---|
| JLink V9 | 主板 SWD 4 针（PA13 SWDIO / PA14 SWCLK / 3V3 / GND）|
| 主板电源 | 接通（VCC + GND）|
| 屏幕板电源 | 接通，屏幕显示正常 |
| 屏幕板与主板之间 | 平时怎么接就怎么接（不要拔 CN11）|

### 2. 双击运行

双击本目录下 **`diag_cn11_check.bat`**，按提示按任意键开始。

测试约 10 秒（不会 halt CPU，不影响主板运行）。

### 3. 把结果发回

测试完成后，目录下会生成 **`diag_cn11_result.log`**，把整个文件内容**复制粘贴**回给固件工程师。

---

## 结果含义（固件工程师看）

诊断结果是两次时间间隔 5 秒的 UART RX 计数器读取，关注 SCREEN 通道（数组第 1 个值）。

```
mem32 0x2000062C 5
2000062C = [SCREEN] [IPAD] [CO2] [O2] [JFC103]
              ^
              这个值是 SCREEN UART (CN11 → 主板) 收到的字节数
```

**第 2 次读 - 第 1 次读 = 5 秒内增量**：

| 增量 | 结论 |
|------|------|
| **~1300 字节** | ✅ CN11 完全工作 |
| ~50-100 字节 | ⚠️ 部分通，电平转换器边界异常 |
| 0 字节 | ❌ CN11 物理层断（电平转换器坏 / 接线松 / 屏幕板没发）|

同时看 SCREEN rx_err（数组第 1 个值在另一行）：
- 0 → 信号干净
- 涨 → 电平/波特率错位

## 故障排查

### 错误 1：JLink 找不到
- 修改 `diag_cn11_check.bat` 第 5 行 `set JLINK=` 后的路径

### 错误 2：连接失败 "Cannot connect to target"
- 确认 JLink 4 针顺序对：SWDIO/SWCLK/GND/3V3（不要插反）
- 确认主板有电（VTref 应显示 ~3.3V）
- 确认 device 名是 STM32F103VE（屏幕板用 GD32F303RC，**别接错板子**）

### 错误 3：sleep 命令不存在
- 部分 JLink 版本无 sleep，手动改成两次单独运行间隔 5 秒
